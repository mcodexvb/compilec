        Help
        
  
        
    
        
      
        Running a program
        
      
        Write your program in the editor and press Run or F10. To check a program without running it, choose Execute, then Compile only (F9). Errors and warnings are underlined in the editor and listed above the output; click one to jump to its line.
        
      
        Leave Prepared input empty to type in the Output panel when your program reads from standard input. Press Enter or select Send to submit a line. Use Send EOF when there is no more input. To display a prompt that has no newline, call fflush(stdout) before reading.
        
      
        For a repeatable run, enter the complete input in Prepared input before pressing Run. This also works when live input is unavailable.
        
    
        
    
        
      
        Files
        
      
        Open the Files tab beside Input to add data files, or to create one and type into it. Your program opens them by name, for example fopen("data.txt", "r"). Files the program writes with fopen(..., "w") are listed under the output, where you can view them, download them, or keep them as input for the next run.

        About C Lab
        
  
        
    
        
      
      
        
        
        C Lab is a C and C++ editor and compiler that runs entirely inside your web browser.
        
        
        It was made by Mainul Hossain for students learning C and numerical methods, so that a program can be written, compiled and run on any computer or phone without installing anything.
        
      
        
    
        
    
        
      
        How it works
        
      
          
        
        1. The compiler is downloaded once. The first time you press Run, the browser fetches a real C compiler (about 25 MB, plus 4 MB the first time you build C++) and keeps it, so later runs start at once, even offline.
          2. 
        
        2. Your program is compiled on your device. The compiler turns your C code into WebAssembly, a compact machine code that every modern browser can run safely.
          3. 
        
        3. The program runs in a sandbox. It gets its own private folder for files and cannot touch anything else on your computer. Nothing is uploaded to a server.
          4. 
      
        
    
        
    
        
      
        What is inside
        
      
        
        
        Clang
        
        
        The C compiler. It reads your program, checks it, reports errors and warnings, and translates it into machine code. Clang is part of the LLVM project and is the same compiler used by Apple's Xcode, Android, Chrome and many universities; C Lab uses version 22.
        
        
        LLVM and LLD
        
        
        LLVM is the toolkit behind Clang that optimises the program (the O0, O1 and O2 settings choose how hard it tries). LLD is the linker, which joins your program with the C library into one runnable file.
        
        
        WebAssembly
        
        
        A standard form of machine code built into every modern browser. Clang and LLD have themselves been compiled to WebAssembly, which is how a full compiler can run inside a web page. Your program is compiled to WebAssembly too.
        
        
        WASI and wasi-libc
        
        
        WASI is a standard way for a WebAssembly program to use files, read input and print output. wasi-libc is the C standard library built on it, providing printf, scanf, fopen, malloc, math.h and the rest.
        
        
        Web Worker
        
        
        The compiler and your program run in a background thread, so the page stays responsive and the Stop button can end a program that never finishes.
        
        
        CodeMirror
        
        
        The editor, which provides syntax colouring, line numbers, bracket matching, search and replace, and the error underlines.
        
      
        
    
        
    
        
      
        Compared with a desktop compiler
        
      
        The C language and library are the same as with GCC in Dev-C++ or Code::Blocks, so a correct program gives the same results. Programs run somewhat slower than a native program, which does not matter for practical classes. See Help for prepared input, live input and virtual files.
